- (event) Web research: nba.com/news/category/power-rankings is a newest-first article list with a 'Load more' button; the first page load should always include the latest week's article. api-hub.nba.com returned HTTP 461 (likely blocked/needs auth), so that path is not usable for a simple scraper. Weekly discovery should use the category page or guess the URL slug (power-rankings-<season>-week-<n>), matching the existing data/articles naming.
- (decision) Playoffs scraper stays manual (npm run scrape:playoffs), not folded into the automated weekly job.
- (decision) Weekly discovery: the job checks nba.com/news/category/power-rankings each run (newest-first listing) and takes whatever's newest, rather than guessing the URL slug by incrementing a week number.
- (decision) Failure gate: a missing new article is only a failure within the known regular-season date window (derived from past seasons' week counts); outside that window (off-season, All-Star break) a missing article is a silent no-op. GitHub Actions' default failure email is sufficient notification; no separate issue-opening.
- (decision) The job commits straight to main with no PR step -- zero-touch over a review safety net, since the brief calls for no manual step during the season.
- (decision) One workflow, not two: a single scheduled job does scrape -> rebuild -> commit -> build -> deploy together, on a weekly cron. Chosen over splitting data-update (scheduled) and deploy (on push to main) into separate workflows; accepted trade-off is that a manual code push doesn't deploy until the next scheduled run.
- (decision) Add workflow_dispatch alongside the cron schedule on that same workflow, so a run can be triggered manually from GitHub's UI. Does not change the one-workflow decision.
- (decision) [ADOPTED] Ratify existing data convention: data/articles/<season>/<slug>.json holds the full article record (including structured rankings when parseable); data/index.json holds a slim pointer record per article ({id, slug, title, season, week, publishedAt, hasStructuredRankings, file}); npm run build:rankings reduces both into src/data/seasons/<season>.json. The new weekly scraper writes into this same shape rather than inventing a new one.
- (decision) [ADOPTED] Ratify existing scraper convention from scripts/scrape-playoffs.mjs: space requests (matching the source's crawl-delay) and identify the scraper with a descriptive user agent. The new weekly scraper follows the same convention.
- (constraint) Idempotency: re-running the weekly job (manual retrigger or retry) must not duplicate or corrupt data/index.json or data/articles -- write/append keyed by article slug, so a rerun against an already-recorded week is a no-op, not a duplicate entry.
