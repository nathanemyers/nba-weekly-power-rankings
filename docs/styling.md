# Styling guide

This site is styled with two libraries. This page is everything you need to change how it looks.

- **[Tailwind CSS](https://tailwindcss.com/docs)** replaces hand-written CSS with small classes you put straight on elements, such as `flex`, `gap-3`, or `text-muted-foreground`. There are no separate style files per component.
- **[shadcn/ui](https://ui.shadcn.com/docs)** is a set of ready-made components (buttons, cards, and so on). Unlike most libraries, it copies each component's source into this repository, so the files are ours to read.

## The theme

The theme is one file: [`src/index.css`](../src/index.css). Every color and corner radius on the site is defined there and nowhere else.

It has two parts that work together:

1. The `:root` block holds the values, each under a name that says what it is for:

   ```css
   :root {
     --card: #2c2c2e;
     --muted-foreground: #a1a1a6;
   }
   ```

2. The `@theme inline` block hands each value to Tailwind:

   ```css
   @theme inline {
     --color-card: var(--card);
     --color-muted-foreground: var(--muted-foreground);
   }
   ```

   A line `--color-NAME` is what makes the classes `bg-NAME`, `text-NAME`, `border-NAME`, `fill-NAME`, and `stroke-NAME` exist. So `--color-card` gives you `bg-card`.

### Roles

Names that shadcn/ui components expect (keep these names):

| Name | Used for |
| --- | --- |
| `background` / `foreground` | Page background / primary text |
| `card` / `card-foreground` | Panels / text on panels |
| `popover` / `popover-foreground` | Chart tooltip / its text |
| `primary` / `primary-foreground` | Emphasized controls / their text |
| `secondary` / `secondary-foreground` | Quiet controls / their text |
| `muted` / `muted-foreground` | Subdued surfaces and pressed cards / muted text, axis labels |
| `accent` / `accent-foreground` | Hover surfaces / their text |
| `destructive` | Error styling |
| `border`, `input`, `ring` | Panel borders, form control borders, keyboard focus ring |
| `radius` | Base corner radius; `rounded-sm` to `rounded-4xl` are derived from it |

Names specific to this site:

| Name | Used for |
| --- | --- |
| `foreground-soft` | Secondary body text, idle team labels, rank numbers |
| `dim` | Team labels pushed back while another team is active |
| `rank-up`, `rank-mid`, `rank-down` | Rising / middle / falling rank, in swing cards and trend minimaps |
| `chart-grid` | Chart grid lines |
| `chart-playoffs` | "Playoffs Begin" line and label |

The typeface is the one value that lives in `@theme inline` instead of `:root`: `--font-sans`.

Team line colors are not part of the theme. They are facts about teams and live in `src/types/nba.ts`.

## Change a value

Edit the value in `:root` and save. For example, to make panels warmer:

```css
--card: #33291f;
```

Every panel, including ones inside library components, follows. The chart and minimaps read the same variables, so changing `--chart-grid` or `--rank-up` restyles them too.

## Add a role

1. Add the value to `:root`: `--highlight: #ffd60a;`
2. Expose it in `@theme inline`: `--color-highlight: var(--highlight);`
3. Use it: `className="text-highlight"`.

## Add a library component

```bash
npx shadcn@latest add separator
```

The file appears in `src/components/ui/`. Import it with the `@/` alias, which points at `src/`:

```tsx
import { Separator } from "@/components/ui/separator";
```

Browse what is available at <https://ui.shadcn.com/docs/components>.

To adjust how a library component looks in one place, pass `className`; your classes win over its defaults:

```tsx
<Button variant="outline" className="px-6">Zoom in</Button>
```

Leave the files in `src/components/ui/` as the CLI wrote them. That keeps `npx shadcn@latest add <name> --overwrite` usable for picking up upstream fixes.

## Where things live

| Path | What |
| --- | --- |
| `src/index.css` | The theme |
| `src/components/ui/` | Library components, generated by the CLI |
| `src/components/` (everything else) | This site's own components |
| `src/lib/utils.ts` | `cn()`, which joins class names and resolves conflicts |
| `components.json` | Settings the shadcn CLI reads |

Library components in use: `button` (Earlier, Later, Zoom), `native-select` (season picker), `card` (rank swings and team summary panels), `badge` ("AI-generated summary"), `toggle` (rank-swing team cards).

## Rules

- **No color values in components.** No hex, `rgb()`, or Tailwind palette classes like `bg-zinc-800`. Use a role. Per-team colors and the generated files in `src/components/ui/` are the only exceptions.
- **Never build a class name from a variable.** Tailwind finds classes by reading the source as text, so `` `text-${color}` `` produces nothing. Write the full class names and choose between them.
- **Run-time values go in `style` or SVG attributes.** A team's color or the chart's width is only known from data, so it is set with `style={{ maxWidth: width }}` or `stroke={team.color}`.
- **State-dependent color uses a `data-` attribute.** For example, team labels set `data-state="active" | "dimmed" | "idle"` and are styled with `data-[state=active]:fill-foreground`. Tests check the attribute, not the color.
- **SVG uses the same roles.** `fill-muted-foreground` and `stroke-chart-grid` work on SVG elements. Gradient stops have no utility, so they use `[stop-color:var(--color-rank-up)]`.
- **Give SVGs inside buttons a `size-` class.** Library buttons and toggles shrink any nested `<svg>` without one to icon size. `TrendMinimap` sets `size-auto` for this reason.
- **Text must stay readable.** Text roles are kept at a contrast of at least 4.5:1 against the surfaces they sit on. `dim` is the deliberate exception.

## Adding a light palette later

The site is dark only. The dark values sit in `:root`, and `<html class="dark">` in `index.html` switches on the `dark:` variants that library components carry.

To add a light palette: move the current color values from `:root` into a `.dark { … }` block, put the light values in `:root`, and add or remove the `dark` class on `<html>` to switch. No component needs to change.

## How this was set up

```bash
npm install tailwindcss @tailwindcss/vite
npx shadcn@latest init -b radix -p nova --no-monorepo --css-variables -y
npx shadcn@latest add button native-select card badge toggle
```

- `-b radix` picks the Radix-based components; `-p nova` picks the "Nova" preset, which the CLI otherwise asks for interactively. The preset only affects the starting palette, which was then replaced by this site's roles.
- The preset also installed the Geist font. It was removed; the site uses the system font.
- The `@/*` alias was added to `paths` in `tsconfig.json` and `tsconfig.app.json`. No `baseUrl` was needed.
- `src/index.css` imports `shadcn/tailwind.css`, which library components rely on for a few shared variants. That is why `shadcn` is listed as a dependency.
