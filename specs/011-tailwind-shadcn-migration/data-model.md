# Data Model: Convert Styling to Tailwind CSS and shadcn/ui

This feature changes no application data. Season, team, ranking, playoff, and summary data and their types are untouched. The "data" here is the theme and how components relate to it.

## Theme

The single definition of the site's look, held in `src/index.css`.

| Part | Contents | Notes |
| --- | --- | --- |
| Values | One `:root` block of named CSS variables | The only place a color or radius value is written |
| Exposure | One `@theme inline` block mapping each color to a Tailwind token, plus the typeface | What makes `bg-card`, `fill-dim`, etc. exist; `--font-sans` is written here directly |
| Variant | `@custom-variant dark` plus `class="dark"` on `<html>` | Keeps library components' dark variants active |
| Base | `body` background, text color, and font from the theme | Replaces the page container's inline styling |

Validation rules: every role in [contracts/theme-tokens.md](contracts/theme-tokens.md) is present exactly once; every color in `:root` is exposed in `@theme inline`; no value appears in any project file outside `src/index.css`.

## Theme role

One named entry in the theme.

| Field | Description |
| --- | --- |
| Name | Purpose-based identifier, e.g. `muted-foreground`, `rank-up` |
| Value | A color, font stack, or length |
| Kind | Standard (required by shadcn/ui components) or project (data meaning and chart) |

Relationships: a role is referenced by any number of components through utilities; a component never holds a role's value.

## Team color

| Field | Description |
| --- | --- |
| Team | The team it identifies |
| Color | That team's line and dot color |

Lives with the team definitions in `src/types/nba.ts`. Not a theme role, not changed by this feature, applied as an inline SVG attribute because it is only known from data.

## Library component

A file under `src/components/ui/`, generated by the shadcn CLI and owned by the project once generated.

| Component | Used for |
| --- | --- |
| `button` | Earlier, Later, Zoom |
| `native-select` | Season picker |
| `card` | Rank-swings panel, team-summary panel |
| `badge` | "AI-generated summary" label |
| `toggle` | Rank-swing team cards |

Rules: reads theme roles only; is not edited to add project behavior (wrap or compose it instead); may be restyled per use with `className`.

## Project component

A component specific to this site, under `src/components/` outside `ui/`.

| Component | Composes | State attributes it exposes |
| --- | --- | --- |
| `App` (page shell) | `button`, `native-select` | none |
| `Chart` | theme utilities on SVG | none |
| `TeamLabels` | theme utilities on SVG | `data-state` on each label |
| `TrendMinimap` | theme variables on gradient stops | `data-band` on each stop |
| `RankSwings` | `card`, `toggle`, `TrendMinimap` | `data-direction` on each change |
| `TeamSummary` | `card`, `badge` | none |
| `GitHubBadge` | theme utilities | none |

State attributes and their values are specified in [contracts/ui-states.md](contracts/ui-states.md).

## State transitions

Team label `data-state`, derived on every render from hover and pin state already owned by `App` and `Chart`:

- No team active → every label `idle`.
- A team becomes active (hover or pin) → that label `active`, all others `dimmed`.
- Active team cleared → every label `idle`.

No new state is stored.
