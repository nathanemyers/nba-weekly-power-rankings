# Implementation Plan: Generate AI Summaries Through Ollama

**Branch**: `master` (spec dir `014-ollama-summaries`; no feature branch created yet) | **Date**: 2026-10-24 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/014-ollama-summaries/spec.md`

## Summary

Swap the model call in `scripts/build-summaries.mjs` from the Anthropic SDK to Ollama's REST API using Node's built-in `http` module, and remove `@anthropic-ai/sdk`. `fetch` is ruled out because it times out after 5 minutes waiting for a slow local model (research.md §1). One setting, `SUMMARY_MODEL`, picks the model: a local one by default, or a `:cloud` model that runs on Ollama's paid cloud through the signed-in Ollama app. The decision rules, the stored file format and the app are untouched, so no completed-season summary changes.

## Technical Context

**Language/Version**: Node 22 ES modules (scripts only)

**Primary Dependencies**: None added; `@anthropic-ai/sdk` removed. Ollama 0.33+ installed by the maintainer, outside the project.

**Storage**: Unchanged — `data/processed/summaries/<season>.json`

**Testing**: Vitest; new module tested with a fake request function passed in, no network

**Target Platform**: The maintainer's machine (measured: RTX 3070 8 GB, 15 GB RAM); optionally Ollama's cloud

**Project Type**: Build-time data script in a static web app

**Performance Goals**: Measured locally with the default model: up to about 8 minutes per team on the longest input, so a 30-team weekly refresh takes up to about 4 hours unattended (research.md §5). The cloud option exists for faster runs.

**Constraints**: No credential in the repo, bundle or CI (FR-009); `--dry-run` and no-work runs never contact Ollama (FR-010); inputs up to about 14,000 tokens must not be truncated (research.md §3); `AGENTS.md` forbids running `build:summaries` from agents, so end-to-end runs are the maintainer's

**Scale/Scope**: 270 team-seasons for a full backfill; at most 30 per weekly run
