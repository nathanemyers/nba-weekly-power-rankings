# Research: URL Routing and On-Demand Season Data

**Feature**: 018-react-router-data-loading | **Date**: 2026-10-26

## R1. Router type

- **Decision**: `createHashRouter` from `react-router` 8.5.0 (already installed), replacing the
  `createBrowserRouter` call on the branch. Addresses look like
  `/nba-weekly-power-rankings/#/2024-25` and `/nba-weekly-power-rankings/#/teamHistory/bos`.
- **Rationale**: GitHub Pages serves only `index.html` at the base path; everything after `#` never
  reaches the server, so deep links load on a fresh request (Principle III, FR-002). No `basename`
  is needed because the hash path is independent of Vite's `base`.
- **Alternatives considered**: Browser router + `404.html` redirect trick (needs a constitution
  amendment and gives a flash of 404); query parameters (awkward for nested routes). Both rejected
  in the spec clarifications.

## R2. Route tree

- **Decision**:
  - `/` → `Root` layout (`<main>` shell, `HydrateFallback`, `ErrorBoundary`)
    - index → loader `redirect('/' + latestSeason)` (FR-007; `replace` semantics come from a
      loader redirect, so no extra Back step)
    - `teamHistory/:team` → `TeamHistoryView`, `id: 'teamHistory'`
    - `:season` → `ChartView`, `id: 'season'`
- **Rationale**: Static segment `teamHistory` outranks the dynamic `:season`, so ordering does not
  matter. Route ids let nested components read loader data with `useRouteLoaderData`.
- **Alternatives considered**: `season/:season` prefix: longer URLs with no benefit.

## R3. Splitting season data into chunks

- **Decision**: Change the generated `data/processed/seasons/index.ts` (written by
  `scripts/build-rankings.mjs`) from static imports to:
  - `seasonIndex`: a small array of `{ name, source, champion? }`, newest first, inlined in the
    main bundle (drives the season picker, its champion logos, and the default redirect);
  - `seasonLoaders`: `Record<string, () => Promise<{ default: unknown }>>` whose entries are
    `() => import("./2024-25.json")`.

  Vite emits each JSON as its own hashed chunk under `dist/assets/`, served same-origin under the
  base path.
- **Rationale**: Dynamic `import()` is base-path safe (Vite rewrites the URL), hashed (cache
  safe), deduplicated by the module system (a second `import()` of the same file does not download
  again), and needs no `public/` copy step or hand-written `fetch`. Keeping the generator as the
  only writer of `index.ts` matches the existing pipeline. `build:rankings` is allowed (only
  `build:summaries` is forbidden). After editing the generator, `index.ts` is regenerated by running
  `npm run build:rankings`, or hand-edited to match if raw inputs are missing locally.
- **Alternatives considered**:
  - `import.meta.glob('./*.json')` in app code: equivalent chunks, but the champion/source index
    would still need a build step, and the season list would come from file names.
  - Copy JSON to `public/` and `fetch()`: needs a copy step and manual base-path handling.
- **Size impact**: Today's single JS file is 7.0 MB raw / ≈2.17 MB gzip, of which ≈6.3 MB raw is
  season JSON. The first load becomes app code (≈0.7 MB raw) plus one season (≈0.35 MB raw), well
  past SC-002's 50% target.

## R4. Where loaded data lives and how views read it

- **Decision**: Loaders hold the data (constitution v1.5.0, State & Data Layer). A shared module
  `src/data/seasonData.ts` exposes `loadSeason(name): Promise<Season>`, which caches the promise in
  a plain object keyed by season name. The cache holds the Zod-parsed `Season`, so a season is
  downloaded and validated once per visit (FR-013). The `season` route loader returns
  `{ season: loadSeason(name) }` *without awaiting*. Views call `use(promise)` inside `<Suspense>`.
  A `useSeason()` hook wraps `use(useRouteLoaderData('season').season)` for nested components
  (RosterPane, RankSwings, TeamSeasonSummary, etc.).
- **Rationale**: Returning an unawaited promise lets the navigation finish at once and puts the
  loading state in React `Suspense` (AGENTS.md rule). The router discards stale navigations, so
  rapid season switching always ends on the last pick. A module-level promise cache avoids both
  re-downloads and re-parsing, using a plain object as AGENTS.md requires.
- **Alternatives considered**: Awaiting in the loader and showing a pending UI through
  `useNavigation()`: works, but it is not Suspense and keeps the old season on screen with no
  loading indicator unless extra UI is added. Dispatching loaded data into Redux was rejected in
  the spec clarification (FR-015).

## R5. Showing the fallback on season switch

- **Decision**: Key the Suspense boundary in `ChartView` by season name
  (`<Suspense key={seasonName} fallback={…}>`).
- **Rationale**: Router navigations run inside a transition; a suspending update inside a
  transition keeps the old UI instead of showing a fallback. A new key mounts a fresh boundary, so
  the fallback appears (Story 3, scenario 2). For cached seasons the promise is already resolved
  and `use()` returns at once, so no fallback flashes (SC-004).
- **Alternatives considered**: `useNavigation()` spinner: does not cover the post-navigation
  suspend.

## R6. Validation of address values

- **Decision**:
  - `:season` is checked against `seasonIndex` names. An unknown season throws
    `redirect('/' + latest)` from the loader (FR-008).
  - `:team` is lowercased and parsed with `z.enum(Team)`. On failure the loader throws
    `data(null, { status: 404 })`, and the route `ErrorBoundary` renders "Team not found" with a
    `Link` to `/`.
  - `seasonIndex` itself is parsed with a Zod `SeasonIndexSchema` at module load, because bundled
    JSON crosses a trust boundary.
- **Rationale**: Constitution Data Validation covers URL parameters. Redirecting an unknown season
  is friendlier than an error. An unknown team has no sensible default.

## R7. Team history data

- **Decision**: The `teamHistory` loader returns `{ seasons: loadAllSeasons() }`, which settles
  every `loadSeason` call (reusing the cache) and keeps only the fulfilled ones, in index order.
  Rejected seasons are logged with `console.error` and skipped (SC-005).
- **Rationale**: This is the spec clarification's choice (download all on open). Skipping failed
  seasons keeps the page usable.

## R8. Redux after the change

- **Decision**: Delete the `seasons` and `UI` slices. The store keeps only `chart` (pinned teams,
  zoom window).
  - Selectors that read the selected season become pure functions of a `Season` (`analysis.ts`,
    roster/coach lookups, AI summary lookup).
  - Window selectors and the `pageWindow` thunk that needed `maxWeek` take it as an argument
    (`getEndWeek(state, maxWeek)`, `pageWindow(delta, maxWeek)`).
- **Rationale**: Constitution v1.5.0 says loaded data lives in exactly one place, and the selected
  season and view come from the URL (FR-001). Passing `maxWeek` in avoids copying season data into
  the store.
- **Alternatives considered**: Dispatching `maxWeek` into the chart slice on load needs a
  `useEffect` and copies loaded data, so it was rejected.

## R9. Pinned teams across navigation

- **Decision**: Keep today's behavior.
  - Choosing a season in the picker clears pins, then navigates.
  - Back/Forward does not touch pins.
  - Clicking a team-history season card pins that team and navigates. This matches today's
    behavior, where the team was already pinned, and keeps it pinned when the page was opened from
    a deep link.
- **Rationale**: FR-016/FR-017. Components already handle a pinned team missing from a season
  (`find` returns undefined).

## R10. Initial render and errors

- **Decision**:
  - `Root` gets a `HydrateFallback` (a minimal skeleton) so the router's first loader pass does
    not warn.
  - The `season` and `teamHistory` routes get an `ErrorBoundary` component that reads
    `useRouteError()`. It renders "Team not found" for a 404, and otherwise "Couldn't load season
    X" with the season picker (FR-011).
  - `SeasonSelect` reads its value from `useParams()` and its options from `seasonIndex`, so it
    works on the error screen without season data.
- **Rationale**: A `use()` rejection is thrown during render and caught by the route error
  boundary. No new dependency (such as `react-error-boundary`) is needed.

## R11. Testing approach

- **Decision**:
  - Export the `routes` array from `src/routes.tsx`. `App` builds a hash router from it; tests
    build `createMemoryRouter(routes, { initialEntries: ['/long'] })` through a
    `renderWithRouter` helper that also supplies the Redux `Provider`.
  - The existing `vi.mock('data/seasons')` fixtures move to the new `seasonIndex` and
    `seasonLoaders` shape, with loaders returning `Promise.resolve({ default: … })`.
  - Tests use `findBy*` queries to wait for Suspense.
- **Rationale**: Memory routers are React Router's documented test path and keep the current
  App-level tests nearly unchanged.
