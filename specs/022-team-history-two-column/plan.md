# Implementation Plan: Two-Column Team History Page

**Branch**: `022-team-history-two-column` | **Date**: 2026-11-12 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/022-team-history-two-column/spec.md`

## Summary

Rebuild the team history page. On desktop (≥1024px) it becomes two independently scrolling columns: a `Seasons` navigation on the left (name, trend minimap, playoff badges) and season detail sections on the right (storylines, top-6 players by total minutes, season-chart link, data source). Clicking a left entry scrolls the right column to that season. Scrolling the right column updates the highlighted entry and nudges the left column so the entry stays visible. Below 1024px the page is a shadcn Accordion of overviews that expand to show the same detail. AI summaries are removed from this page. All of this is client-side, derived from season data already loaded. Scroll syncing runs in event handlers (no `useEffect`, no `useRef`); see [research.md](research.md).

## Technical Context

**Language/Version**: TypeScript 5 / React 19

**Primary Dependencies**: Vite, Tailwind CSS v4, shadcn/ui (adds `accordion`, built on the existing `radix-ui` package), React Router (hash router), Redux Toolkit (only `setPinnedTeams` for the chart link)

**Storage**: N/A. Uses the existing `data/processed` season modules; no data changes

**Testing**: Vitest + Testing Library (`npm test`), with a manual scroll check in the built-in browser (jsdom has no layout)

**Target Platform**: Static site on GitHub Pages; current desktop and mobile browsers

**Project Type**: Single-page web app (frontend only)

**Performance Goals**: Highlight follows the right column's scroll with no visible lag; a click-scroll settles within 1s (SC-002)

**Constraints**: No backend; AGENTS.md rules (no `useMemo`, minimal `useEffect`, no `useRef` for state, Tailwind classes only with no dynamic class names, colors only in `src/index.css`, shadcn components, `cursor-pointer` on clickables, no `Map`/`Set`)

**Scale/Scope**: About 25 seasons per team, up to 6 players and ~10 storylines per season; one route, about 6 components

### Existing tests that change

`src/App.test.tsx` has team-history cases that depend on old behavior:

- `"names each season's source in the team history"` expects one "AI-generated summary". Change it to expect none.
- `"goes from the chart to the history and back to a season with the team pinned"` and `"pins the team when a card is opened from a shared history link"` click a season heading to navigate. Change them to click the `View <season> chart` link.
- `"shows on team history cards without leaving the history when clicked"` clicks a playoff badge. It should still pass; check the button index still points at a badge and not the stretched season button.

## Key Implementation Notes

- **Viewport layout** (research §2): `TeamHistoryView` root becomes `flex flex-col lg:h-[calc(100dvh-4rem)]`; the h1 is `shrink-0`; the TeamHistory desktop grid is `min-h-0 flex-1 grid grid-cols-[auto_1fr] gap-6`, and both columns are `overflow-y-auto`. On the narrow layout the root keeps its natural height.
- **Lookups without refs**: each column gets an `id` from `useId()`. Handlers use `document.getElementById(id)` and `querySelector('[data-season="…"]')`. The scroll spy uses `event.currentTarget`.
- **Highlight styling**: the active left entry uses static classes chosen by a boolean (e.g. `bg-muted ring-1 ring-ring` vs `hover:bg-muted/50`), with `cursor-pointer`. No dynamic class strings.
- **Stretched button** (research §7): season `<button>` with `after:absolute after:inset-0`; the playoff badge wrapper is `relative z-10`.
- **Player badge**: `Badge asChild variant="outline"` over `Link`, full name, `cursor-pointer hover:bg-muted`.
- **Remove**: the `aiSummary` paragraph and the "AI-generated summary" badge on this page, and the old card-level `onClick` navigation. `TeamSeasonSummary.tsx` stays as is.
